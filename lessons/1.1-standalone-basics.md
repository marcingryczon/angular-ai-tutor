# Lekcja 1.1: Podstawy standalone component

## Cel lekcji
Opanowanie `@Component`, metadata, bootstrapu oraz paradygmatu standalone vs NgModule.

---

## `@Component()` — metadata

```ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-greetings',
  template: '<h1>Hello from Greetings component</h1>'
})
export class Greetings {}
```

- **`selector`** — selektor CSS, którym komponent jest wywoływany w szablonie rodzica.
- **`template`** — inline HTML (dla małych szablonów) vs **`templateUrl`** — zewnętrzny plik (dla większych).
- **`styles`** / **`styleUrl`** — analogicznie dla stylów. Opcjonalne — nie dodawaj pustych `styles: ''`.
- **`imports`** — lista komponentów/dyrektyw/pipes używanych w szablonie tego komponentu.

**Kluczowa zasada:** komponent używany w szablonie MUSI być w `imports` komponentu rodzica — inaczej błąd kompilacji „not found in scope".

---

## Standalone vs NgModule

- Od Angular 19 `standalone: true` jest **domyślne** — nie trzeba go nawet pisać.
- Standalone = komponent jest **samodzielny**: sam deklaruje, czego potrzebuje (`imports`), bez centralnych list `declarations`/`exports` w module.
- Dzięki temu nie ma „dużego modułu" do podtrzymywania — importujesz komponent tam, gdzie go używasz.

## Bootstrap

- `bootstrapApplication(App, appConfig)` (funkcjonalny bootstrap, `main.ts`) — nowoczesny sposób.
- Angular szuka `<app-root>` w `index.html` i zastępuje go treścią komponentu root.

## Ćwiczenie treningowe (`src/app/`)

- `src/app/1.1-standalone-basics/greetings.ts` — minimalny standalone komponent z inline template.
- Zaimportowany w `src/app/app.ts` (`imports: [Greetings]`) i wyrenderowany w `app.html`.

### Wnioski z weryfikacji
- Kompilator Angulara **sam wykrywa nieużywane importy** (np. `RouterOutlet` bez `<router-outlet>` w szablonie) — traktuj te błędy jako sojusznika.
- Nazwa pliku ma odpowiadać nazwie klasy (`greetings.ts` → `class Greetings`).

## Zastosowanie w projekcie (`projects/taskflow/`)

Pierwszy komponent TaskFlow — **statyczny board shell**:

- `features/board/board.ts` — standalone, `templateUrl` + `styleUrl` (nic inline w dekoratorze).
- `board.html` — nagłówek (back link, tytuł „Marketing Sprint", badge `Team`, opis) + 4 kolumny (To Do / In Progress / Review / Done) z count pillami i pustym stanem.
- `board.scss` — układy: grid `repeat(4, minmax(0, 1fr))` (kolumny się kurczą, brak poziomego scrolla).
- `styles.scss` (globalny) — tokeny `:root` ze spec + reset + klasy fontu ikon.

### Pułapka, na którą natrafiliśmy
Klasa wariantowa ikon (`material-symbols-rounded--sm`) **nie jest samowystarczalna** — ustawia tylko rozmiar. Trzeba łączyć ją z klasą bazową:

```html
<span class="material-symbols-rounded material-symbols-rounded--sm">arrow_back</span>
```

## Podsumowanie

- Standalone to domyślny, samodzielny paradygmat — `imports` zastępuje moduły.
- `template`/`templateUrl` i `styles`/`styleUrl` — inline vs pliki, oba poprawne.
- W TaskFlow: tokeny globalne w `styles.scss`, układy per-komponent w jego `.scss`.
