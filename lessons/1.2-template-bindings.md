# Lekcja 1.2: Wyzrażenia szablonu i binding

## Cel lekcji
Interpolacja, property binding, event binding i two-way binding w szablonach Angulara.

---

## Cztery mechanizmy bindingu

| Składnia | Kierunek | Co robi |
|---|---|---|
| `{{ value }}` | klasa → DOM | Interpolacja — wstawia wartość, **escape'uje HTML** (bezpieczna) |
| `[prop]="value"` | klasa → DOM | Property binding — przypisuje do property JS elementu (`[disabled]`, `[style.color]`, `[class.x]`) |
| `(event)="handler()"` | DOM → klasa | Event binding — słucha zdarzenia i woła metodę |
| `[(x)]="value"` | obie strony | Two-way — skrót od `[x]` + `(xChange)` |

**Sygnał w szablonie to funkcja** — zawsze `{{ count() }}`, nie `{{ count }}`.

## `[style.x]` vs `[class.x]`

- `[style.color]="warunek ? 'czerwony' : 'niebieski'"` — prosta, dynamiczna wartość inline.
- `[class.nazwa]="warunek"` — klasa w SCSS; preferowane przy złożonych stylach (separacja treści i wyglądu).

## Ćwiczenie treningowe (`src/app/`)

`1.2-template-bindings/counter/` — licznik z sygnałem `count`, przyciskami +/− i Reset:

- `{{ count() }}` — interpolacja
- `(click)="increment()"` — event binding
- `[style.color]="count() < 0 ? 'var(--danger)' : 'var(--text)'"` — property binding z ternary

### Pułapka, na którą trafiliśmy: `:root` w stylach komponentu

```scss
/* ❌ martwy kod — Angular enkapsuluje selektory: :root[_ngcontent-x] pasuje do niczego */
:root { --danger: red; }

/* ✅ zmienne komponentu na :host */
:host { --danger: red; }
```

Style komponentu są enkapsulowane (Angular dodaje atrybut `_ngcontent-*` do selektorów). `:root` w scoped styles nie trafi do elementu `<html>` — zmienne CSS należy definiować na `:host` (komponent) albo globalnie w `styles.scss`. Pełne omówienie: lekcja 1.5.

## Zastosowanie w projekcie (`projects/taskflow/`)

Dynamiczne liczniki zadań w kolumnach boarda:

```ts
readonly tasks = [ /* 5 seed tasks ze spec */ ] as const;

countFor(status: TaskStatus): number {
  return this.tasks.filter(task => task.status === status).length;
}
```

```html
<span class="column__count">{{ countFor('todo') }}</span>
```

Wynik: To Do **2** · In Progress **1** · Review **1** · Done **1**.

### Zasady, które tu wypracowaliśmy

1. **Nie trzymaj kopii stanu, który da się policzyć** — 4 sygnały `inTodoCount` itd. zastąpiła jedna metoda `countFor`. Jedno źródło prawdy.
2. **Metoda z `void` nie może zwracać wartości** — `countFor(...): void` z `return` = błąd typu.
3. **Plik TS bez `import`/`export` to globalny skrypt** — jego typy są widoczne wszędzie, ale to kruche (dodanie `export` zrywa globalny scope). Poprawnie: `export` + jawnego `import`.
4. **Nieużywany import to błąd** — `OnInit` po usunięciu `implements` musiał wyjść z importu (taki sam mechanizm jak `RouterOutlet` w lekcji 1.1).

## Podsumowanie

- 4 mechanizmy bindingu: `{{ }}`, `[ ]`, `( )`, `[( )]` — każdy o innym kierunku przepływu danych.
- `[style.x]` dla prostych wartości, `[class.x]` dla złożonych.
- Zmienne CSS komponentu: `:host`, nie `:root`.
- Licz mi się policzone, nie zapamiętywane: metoda > kilka sygnałów.
