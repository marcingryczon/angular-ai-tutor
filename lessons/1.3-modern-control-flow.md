# Lekcja 1.3: Modern Control Flow

## Cel lekcji
Zastąpienie `*ngIf`/`*ngFor` nowymi blokami `@if`, `@else`, `@for`, `@empty`, `@switch` — bez importów, z wymuszonym `track`.

---

## Dlaczego Angular wprowadził bloki

| Stara (v15−) | Nowa (v17+) | Import? |
|---|---|---|
| `*ngIf="cond"` | `@if (cond) { ... }` | `NgIf` w `imports` | **zbudowane, zero importów** |
| `*ngFor="let x of arr"` | `@for (x of arr; track ...) { ... }` | `NgFor` w `imports` | **zbudowane** |
| — | `@switch` / `@case` / `@default` | — |

`*ngIf`/`*ngFor` to *microsyntax* nad dyrektywami strukturalnymi — Angular musiał rozpakowywać `ngTemplateOutlet`. Bloki `@if`/`@for` są pierwszoklasowym składnikiem parsera: prościej je analizować, optymalizować i kompilować. Mniejszy bundle, lepszy i18n.

## `@for` i `track`

```html
@for (task of tasks; track task.id) {
  <div class="task-card">{{ task.title }}</div>
} @empty {
  <p>No tasks</p>
}
```

**Co robi `track`?** Angular musi wiedzieć, czy element to ten sam węzeł DOM co przed chwilą, czy nowy. Bez `track` kluczem jest **pozycja w tablicy** — przesunięcie elementu = zniszczenie i ponowne zbudowanie węzłów DOM (utrata focusu, animacji, scrolla). Z `track task.id` Angular **przesuwa ten sam węzeł**.

**Złota zasada:** `track` zawsze po stabilnym, unikalnym identyfikatorze (`id`). Nigdy `title` (może się powtórzyć), nigdy `status` (wielokrotny). Stąd w modelu domeny TaskFlow każde zadanie ma `id`.

**`@empty`** — wbudowany blok „gdy tablica pusta" (stary `*ngFor` tego nie miał). Musi iść bezpośrednio po `@for`, na tym samym poziomie.

## `@if` / `@else`

```html
@if (item.paid) {
  <span>check</span>
} @else {
  <span>close</span>
}
```

Bloki mogą być **zagnieżdżone** (np. `@if` wewnątrz `@for`) — w starym `*ngIf`+`*ngFor` na tej samej linii było to problematyczne.

## Ćwiczenie treningowe (`src/app/`)

`1.3-modern-control-flow/status-list/` — tabela płatności:

- `@for (item of items; track item.id)` — 4 pozycje
- `@if (item.paid) { check } @else { close }` — ikona per pozycja
- `[class.green]="item.paid" [class.red]="!item.paid"` — warunkowe klasy (lekcja 1.2)
- `@empty { <tr><td colspan="2">Brak pozycji</td></tr> }` — zweryfikowane na żywo z pustą tablicą

### Pułapki, na które trafiliśmy

1. **`<h2>` wewnątrz `<table>`** = niepoprawny HTML (nagłówki nie mogą siedzieć w tabeli). `@empty` musi iść wewnątrz `@for` (składnia), więc komunikat pustej tabeli to **wiersz z `colspan`**, nie nagłówek.
2. **`[class]="{a: cond}"` (object syntax)** — działa, ale nieczytelne. Standard: `[class.a]="cond"` per klasa.
3. **`<thead>`/`<tbody>`** — poprawna semantyka tabeli (przyda się w Phase 12, dostępność).

## Zastosowanie w projekcie (`projects/taskflow/`)

Board renderowany dwupoziomowo przez `@for`:

```ts
readonly columns: Column[] = [/* 4 kolumny */] as const;
readonly tasks: Task[] = [/* 5 seed tasks ze spec */] as const;

countFor(status: TaskStatus): number {
  return this.tasks.filter((t) => t.status === status).length;
}
taskFor(status: TaskStatus): readonly Task[] {
  return this.tasks.filter((t) => t.status === status);
}
```

```html
@for (column of columns; track column.id) {
  <section class="column">
    <h2>{{ column.title }}</h2>
    <span class="column__count">{{ countFor(column.status) }}</span>
    @for (task of taskFor(column.status); track task.id) {
      <article class="task-card">{{ task.title }} ({{ task.priority }})</article>
    } @empty {
      <p class="column__empty">No tasks</p>
    }
  </section>
}
```

Wynik: To Do **2** · In Progress **1** · Review **1** · Done **1**.

### Zasada wypracowana

**Jedno źródło prawdy:** licznik (`countFor`) i karty (`taskFor`) liczą z tej samej tablicy `tasks` — nie mogą się rozjechać. Nie trzymaj kopii stanu, który da się wyprowadzić.

## Podsumowanie

- `@if`/`@for`/`@empty` to zbudowane bloki — zero importów, prostsza kompilacja.
- `track` zawsze po unikalnym `id` — tożsamość węzłów DOM, nie pozycja.
- `@empty` wewnątrz `@for`, na tym samym poziomie; w tabeli = wiersz z `colspan`.
- Licz i renderuj z jednego źródła prawdy.
